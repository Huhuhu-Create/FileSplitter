## 关键技术决策（踩坑记录）

### 1. 分卷 ZIP 的收尾结构
- **EOCD 之后绝对不能再写 `PK\x05\x06`**。早期实现多写了一个，Python zipfile 直接判 "File is not a zip file"。
- **EOCD 的 `diskNumber`/`cdDiskNumber`、中央目录条目的 `diskNumberStart` 一律写 0**。
  写真实卷号（如 10/5）会让 .NET `ZipArchive` 抛「不支持拆分或跨区的存档」，无法解压。
  写 0 后末卷表现为「普通单卷 zip」，7-Zip/合并脚本都能正常读；中间片仍带 `PK\x07\x08` 标记保留分卷语义。

### 2. 偏移计算必须用「逻辑字节流」
所有偏移（Local Header、中央目录、ZIP64 Locator）**只累计真实数据字节**，
不含分卷结束标记（4B）与偶数补位（0/1B）。
→ 各卷顺序拼接、剥掉标记后就是一个完全自洽的普通 zip。
（之前用物理文件长度累加，导致 `cdOffset` 多了 40 字节，中央目录指向空白区。）

### 3. merge.bat 必须「还原原文件」而不是「还原 zip」
`merge.ps1` 流程：拼分卷（剥中间片标记）→ 临时 `.zip.tmp` →
`System.IO.Compression.ZipArchive` 取唯一条目流写出 → 体积校验 → SHA-256 校验 → 删临时文件。
已验证：5MB 中文名文件，6 分卷，删原文件后合并，md5 完全一致。

### 4. VerifyVolumeSet 的两处逻辑错误
- 原来要求**每一卷**都以 `PK\x03\x04` 开头 → 第 2 卷起必然误报。正解：只有第 1 卷查 LFH，中间卷查尾部 `PK\x07\x08`，末卷查 EOCD。
- 连续性判断写成 `count == i - 1`（恒真）→ 永远误报缺卷。正解：改为扫描目录收集实际存在的卷号，再比对连续性。

## 构建环境坑
**不要在 Git Bash 里用引号包裹的绝对 Windows 路径调 `g++.exe`** —— cc1plus 找不到临时目录，
表现为 `EXIT=1` 且日志为空。正解：把工具链目录加入 `PATH` 再调 `g++`（build.bat 已这样做）。
编译器：`E:\Dev-Cpp\MinGW64\bin`（GCC 10.3.0, MSYS2 构建），静态链接一次通过。
